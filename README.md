# note-todo

SPA для заметок со списками задач. Заметка состоит из названия и списка пунктов (чекбокс и текст).

Стек: Nuxt 4 (`ssr: false`), Vue 3 Composition API, TypeScript strict, Pinia, SCSS, Vitest. UI-библиотеки и библиотеки для undo/redo и синхронизации стора не используются, все компоненты, модалки и история написаны вручную.

## Запуск

### Docker

```bash
docker compose up --build
```

Приложение откроется на http://localhost:3000.

Сборка двухстадийная: на первой стадии `nuxt generate` собирает статику, на второй ее раздает nginx с fallback на `index.html`, чтобы прямые ссылки вида `/notes/<id>` и обновление страницы работали.

### Локально

Нужны Node.js 22+ и pnpm 10 (версия закреплена в `packageManager`, удобно включить через `corepack enable`).

```bash
pnpm install
pnpm dev
```

## Структура

Монорепозиторий на pnpm workspaces:

- `apps/web` - приложение на Nuxt (`@note-todo/web`);
- `packages/ui` - своя дизайн-система (`@note-todo/ui`): кнопки, иконки, поле ввода, чекбокс, карточка, модалка с focus-trap, модалка подтверждения.

Основное в `apps/web/app`:

- `stores/notes.ts` - стор заметок и сохранение в localStorage;
- `stores/confirm.ts` - стор модалки подтверждения, один хост на все приложение;
- `composables/useNoteEditor.ts` - логика страницы редактирования;
- `composables/useNoteHistory.ts` - undo/redo;
- `composables/useTextCommit.ts` - фиксация текстового ввода в историю;
- `composables/useHistoryHotkeys.ts` - горячие клавиши;
- `utils/storage.ts` - чтение и запись localStorage, черновики;
- `tests/` - тесты истории и стора.

## Принятые решения

### Валидация

- Пустое название - ошибка под полем, сохранить нельзя.
- Пустые пункты молча удаляются при сохранении.

### Подтверждения

- Удаление заметки, отмена редактирования и восстановление черновика подтверждаются через свою модалку (без `alert`/`confirm`).
- Подтверждение отмены редактирования показывается всегда, даже если изменений не было: в ТЗ подтверждение требуется без оговорок.
- Модалка: Teleport, закрытие по Escape, focus-trap, блокировка скролла, ARIA-атрибуты.

### История (undo/redo)

- Используется паттерн «команда»: хранятся операции с данными для отката (старое и новое значение, удаленный пункт и его индекс), а не копии заметки. Так 50 записей не означают 50 полных копий.
- Типы операций: изменение названия, изменение текста пункта, отметка пункта, добавление и удаление пункта.
- Непрерывный ввод в поле дает одну запись: она фиксируется по паузе 700 мс или по уходу фокуса с поля.
- Отметка, добавление и удаление пункта - отдельные записи.
- Новое действие после отката очищает redo.
- Лимит 50 записей, самые старые вытесняются.
- «Сохранить» и «Отменить редактирование» сбрасывают историю.

### Горячие клавиши

- Ctrl+Z / Shift+Ctrl+Z (на macOS также Cmd) работают на странице редактирования глобально.
- Когда фокус в текстовом поле, срабатывает нативный undo браузера, чтобы не было конфликта.
- Пока открыта модалка, горячие клавиши отключены.

### Хранение

- Данные лежат в localStorage вместе с версией схемы (`version`).
- Запись идет не на каждое изменение: с задержкой 500 мс (debounce), а при скрытии вкладки (`visibilitychange`) отложенная запись выполняется сразу.
- Сейчас версия схемы одна, поэтому миграций нет. При смене формата данных будут добавляться миграции vN -> vN+1.
- Битые данные в хранилище не роняют приложение, загружается пустой список.

### Черновики

- Несохраненное редактирование сохраняется как черновик: для новой заметки под ключом `note-todo:draft:new`, для существующей под `note-todo:draft:<id>`.
- Черновик пишется, только если заметка действительно отличается от сохраненной.
- При возврате на страницу предлагается восстановить черновик.
- Срок жизни черновика 7 дней. При старте приложения удаляются просроченные черновики и черновики удаленных заметок.

### Несколько вкладок

- Изменения синхронизируются между вкладками через событие `storage`.
- Если заметку, открытую на редактирование, удалили в другой вкладке, показывается модалка с предложением вернуться на главную.

### Edge-cases

- Несуществующая заметка по URL: страница «Такой заметки не существует» с кнопкой на главную.
- id заметок и пунктов генерируются через `crypto.getRandomValues`, потому что `crypto.randomUUID` доступен только в безопасном контексте (https или localhost).
